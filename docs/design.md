# tomarigi-desktop 設計

AI コーディングエージェント（Claude Code / Codex）のセッションを、常に最前面に浮かぶ窓の鳥で見守る macOS アプリ（Tauri 2）。Chrome 拡張版の tomarigi をデスクトップアプリにしたもの。

## 機能の範囲

- 3 タブ「にわ」「止まり木」「イベント」（既定は「にわ」）、⚙ の設定画面
- Claude Code / Codex の transcript をアダプタ経由で並行監視する。状態判定はローカルのヒューリスティックだけで行い、エージェント側に hook は入れない
- 鳥の状態表示（スプライト・working のオーラ・motion のアニメ）、にわのドラッグ配置と巣箱
- アイコンセット（birds / gnome / cat / robot / frog）のプロジェクト別割り当て
- Web Audio の鳴き声（ミュート・音量）、speechSynthesis の読み上げ（オプトイン・音量）、BYOK（OpenAI / Anthropic）の done 要約と接続テスト
- イベント発火履歴の永続化とデバッグダイアログ
- i18n（`scripts/locales` → `public/_locales` の生成と 43 ロケールの検証）
- mock モード（プリセット＋JSON 注入）

## デスクトップ版の作り

- 監視フォルダ: Rust 側でファイルを読む。Claude Code と Codex の標準の置き場所 `~/.claude/projects`・`~/.codex/sessions` は既定として常に監視する（起動のたびにアプリが持つ値。保存した登録リストには入れない）。ほかのフォルダは設定画面から追加（ネイティブのフォルダ選択）でき、削除できるのは追加したものだけ。`CLAUDE_CONFIG_DIR` で別の設定ディレクトリを使う人は、その `projects` を追加する
  - 既定は一覧の先頭に並べ、「既定」バッジを付け、削除ボタン（×）は出さない
  - 実在しない既定フォルダは監視せず、一覧にも出さない
  - ラベル編集は既定にも残す。既定のラベルは別に保存する
  - 以前の版が「初回に自動登録」で保存した登録のうち、既定と同じパスのものは読み込み時に捨てる（二重に監視しない）
  - ラベルの下にパスを出す
  - 読み取り許可の概念が無いので、フォルダが無い・読めないときは「読めない」バッジだけ出す
- 窓: NSPanel（tauri-nspanel）の浮遊窓。透明・枠なし・常に最前面・全画面スペースの上にも出る。窓の背景のどこを掴んでも動き、位置と大きさは次回起動時に復元する。初回（保存した位置が無い・どのディスプレイにも載らない）はメインディスプレイの右上に置く。窓に影を付ける
- アプリが動いている間ずっと監視する。Dock には出さずメニューバーのアイコンで操作する（左クリックで表示/非表示、右クリックでメニュー）。メニューの文言はシステムの言語が日本語なら日本語、それ以外は英語
- ヘッダーの右端の × で窓を隠す（メニューバーのアイコンから戻す）
- 多重起動しない（tauri-plugin-single-instance）。2 つ目の起動は既存の窓を出して終わる
- メニューバーのアイコンは `src-tauri/icons/tray.png`（テンプレート画像。Tauri のトレイは PNG しか受けない）
- Info.plist に `LSUIElement` を入れる（起動時に Dock に一瞬出るのを防ぐ）
- デバッグダイアログの「保存」は Rust が `~/Downloads/tomarigi-eventlog-<project>.json` に書く。同名ファイルは上書きせず " (1)" 等を付ける
- mock モードは環境変数 `TOMARIGI_MOCK=1` で起動すると `index.html?mock=1` を開く
- ファイル読み: `src/lib/native-fs.ts` が FileSystemDirectoryHandle / File のうち使うメソッドだけを同じ形で持ち、Rust の `fs_list` / `fs_stat` / `fs_read` を呼ぶ。`@/` は `src` を指す

## Ghostty のペインへ移る

- 鳥（にわ）や行（止まり木・イベント・巣箱の一覧）をクリックすると、その claude が動いている Ghostty のペインへ移る。ひなの行は親のペインへ移る
- 対応づけは `<config>/sessions/<pid>.json` の `sessionId` → pid → `ps` の tty → Ghostty AppleScript の `tty of terminal` で `focus` + `activate`
- 対応が取れないセッション（Codex・終了済み）はクリックしても何もしない
- にわは 4px 未満しか動かさずに離したらクリック（左ボタンだけ）。それ以上動かしたらドラッグ
- 移れる要素はカーソルを指にする。マウスを載せたときの説明の表示は出さない

## 終わったセッションの鳥を消す

- プロセスが終わったセッションの鳥は、30 分を待たずにすぐ消す。判定はペインではなくプロセスの生死で行い、端末の種類に依存しない（ペインを閉じると中の claude も終わるため）
- Claude Code: `<config>/sessions/<pid>.json` の sessionId と pid を `ps` で突き合わせ、pid が生きていないセッションは次の読み込みで鳥をフェードで消す。`/exit` で終えたときも同じ。ひなは親と一緒に消す
- `<config>/sessions` が無い（古い版の Claude Code）監視フォルダでは 30 分で消す
- 誤って消さない: `ps` が失敗した回と、`sessions/*.json` の解析に失敗したファイルがあった回は何も消さない。消すのは続けて 2 回の読み込みで見えなかったとき
- Codex: 同じ仕組みが無いので 30 分で消す

## 返事待ちの「?」

- ユーザーの判断待ちで止まっている鳥に「?」を付ける。ツールを使わず「どれにしますか。」のような文章で聞いて止まったターンも対象にする
- 状態は 2 フィールドに分けて持つ
  - 機械判定 `BirdState`: `working | waiting | done | dozing`。`waiting` は AskUserQuestion / ExitPlanMode / request_user_input で止まっているとき。毎ポーリング transcript から再計算する
  - Jev 判定: `pending | asking | not_asking | error` と yes の確率。機械判定が done になったターンだけ、最後の応答文（`assistantText`、末尾 2000 字）を TypeSafe の Jev（`POST https://api.typesafe.ai/v1/systemone`、`jev-latest`、Noul 1 問）に渡す。結果はターン（sessionId＋最終応答の時刻）に紐づけて持ち、ポーリングのたびに呼び直さない
- 「?」の表示 = 機械判定が waiting、または機械判定が done / dozing かつ Jev 判定が asking。pending / error では付けない。次に working になれば消える
- 「?」が付いた鳥は、dozing になっても巣箱にしまわず、にわに残す
- 「?」が付いている間は、鳥の下のイベントの印（完了の ✓・応答待ちの「?」）を出さない
- Noul の基準: yes = 選択肢の提示・承認の要求・情報の質問など、ユーザーが答えないと次に進めない状態で止まっている。no = 作業を終えて報告しただけ（答えなくても困らない添え書きを含む）
- TypeSafe の API キーは BYOK の 3 つ目の提供元（保存・削除・接続テスト）。キーが無ければ Jev 判定はせず、機械判定の waiting だけで「?」を付ける
- 「?」は全アイコンセット共通のバッジを鳥に重ねる。asking の閾値は確率 0.5（定数 1 か所）。done の鳴き声・読み上げは Jev の結果を待たない。判定結果はデバッグダイアログのログに出す。応答文は untrusted input として扱い、Jev の出力は確率としてしか使わない

## ウィンドウモード

- 「浮遊窓 / 通常の窓」を切り替えられる。入口は設定画面とメニューバーのメニュー
  - 浮遊窓: NSPanel（透明・枠なし・常に最前面・全画面スペースの上にも出る）
  - 通常の窓: タイトルバーの信号ボタンで最大化・フルスクリーンができる。最前面には固定しない。Dock・Cmd+Tab・アプリ名のメニューバーに出す（activation policy を Regular）。浮遊窓に戻したら Accessory に戻す
- 窓の背景は半透明にし、後ろを macOS のすりガラス効果でぼかす（画面に居座る圧迫感を減らすため）。文字・鳥・吹き出しは今の濃さのまま読めること。透明度は固定値（`src/perch/perch.css` の `.page` と `.garden`）
- 窓を広げたとき、止まり木と最近の動きは最大幅（720px 前後）で中央に寄せる。設定画面は最大幅 560px で中央。にわは幅いっぱい
- 選んだモードは保存して次回起動時も使う。既定は浮遊窓。位置と大きさはモードごとに別に保存する

## セリフの吹き出し

- ターンが終わったとき（done）だけ、最後の応答を BYOK の OpenAI / Anthropic で短く要約して出す（`src/lib/summarize.ts`）。次のターンが始まる（working）まで出したまま。要約の呼び出しはターンごとに 1 回。キーが無ければ出さない
- にわ: 鳥の名前はアイコンの上。アイコンのすぐ下に全角 15 字ほどの吹き出しを出し、上向きのしっぽで鳥を指す。左右に寄せた吹き出しでも、しっぽはアイコンの真下に残す。状態の行・足元の数・印は吹き出しの下に続く。はみ出す分は「…」で切り、マウスを載せると全文。吹き出しどうし・鳥と重なってよいが、ターンの終わりが後のものほど上に重ねる
- 止まり木: 行の中に同じ要約を 1 行で出す
- 最近の動き: 各行にそのターンの同じ要約を 1 行で添える。追加の要約呼び出しはしない。要約は保存しないので、再起動前の出来事には出ない
- 返事待ちの鳥では、吹き出しに「何を聞かれているか」を出し、状態の行は「返事待ち · 経過時間」だけにする
  - 質問ツール（AskUserQuestion 等）で止まっているときは、ツールの入力にある質問文をそのまま短くして出す（キーが無くても出る）
  - Jev が asking と判定し、要約用のキーが無いときは、最後の応答文の最後の 1 文を AI を使わずに出す

## 状態の呼び名

- ターンを終えた状態は、鳥の状態・最近の動き・音の設定のボタン・鳥の説明のすべてで「完了」にそろえる（43 ロケール）
- 返事を待っている状態は、鳥の状態・最近の動きのイベント・音の設定のボタンのすべてで「返事待ち」にそろえる（43 ロケール）

## 見守り中

- 別のセッションに作業を任せて待っているセッションを「見守り中」で表す。任せた先は同じディレクトリとは限らない
- つながりの取り方: Claude Code のセッション間メッセージ（cross-session messaging。v2.1.224 以降で設定なしに有効な公開機能）の跡を transcript から読む。送った側は SendMessage のツール呼び出しの宛先の名前、受けた側は `<cross-session-message from-name="…">`。名前は `<config>/sessions/<pid>.json` の `name` と突き合わせて相手の sessionId・cwd・status を引く。メッセージを 1 回でもやり取りした 2 つのセッションを「つながっている」とみなす。特定の個人の道具（セッションを起動するスクリプト等）には頼らない
- 見守り中: 自分の機械判定が done / dozing で、つながっている相手のうち working（`sessions/<pid>.json` の status が busy、または相手の transcript の機械判定が working / waiting）のものが 1 つでもあるとき。相手が全部止まるまで done の鳴き声・読み上げを出さない
- 見せ方:
  - にわでは、見守り中の鳥と相手の鳥をすぐ近くに寄せて置き、ひとまとまりを角丸のブロックで囲む。鳥どうしを線でつながない
  - ブロックの上に見守り中の鳥（親）の名前を 1 つ出す。中の鳥は、親と同じフォルダなら名前を出さず、別のフォルダなら親からの相対パスだけを出す
  - ブロックの中の鳥をドラッグすると、ブロックごと動く
  - 見守り中の鳥の足元に、今動いている相手の数を出す
  - 止まり木では相手の行を見守り中の行の下に字下げして並べ、ラベルは見守り中の cwd からの相対パス（配下でなければフォルダ名）。同じフォルダの相手の行は名前を出さない
  - 相手が「?」になっても見守り中の鳥には「?」を付けない。「?」は実際に聞いている鳥だけに付ける
- 見守り中が外れても、つながっている相手が最後に動いてから 5 分は巣箱にしまわない（相手のターンの合間ごとに鳥が巣箱に出入りしないため）。相手の status が idle 以外（shell など）のときも「動いている」に数える
- 字下げの親は、つながっている 2 つのうち先に起動した方。Codex には同じ機能が無いので対象外
- 前提の危うさ: transcript の形式と `sessions/<pid>.json` は Claude Code の公開仕様ではない（sessions のドキュメントに「internal to Claude Code and changes between versions」）。状態判定・Ghostty への移動も同じものに頼っている

## BYOK の API キー

- API キー（OpenAI / Anthropic / TypeSafe）は、普段使いの版では macOS のキーチェーンに保存する（WebView の IndexedDB は平文のファイルで、同じユーザーの他のプロセスから読めるため）
- 保存先は起動時に identifier で 1 か所で決める。普段使い（`net.mohtech.tomarigi-desktop`）と verify（`.verify`）はキーチェーン、dev（`.dev`）は IndexedDB（dev は署名が毎回変わり、ビルドのたびにキーチェーンの許可を聞かれるため）
- verify は手元の Apple Development 証明書で署名し、ビルドし直しても許可を聞かれないようにする
- キーチェーンの項目は identifier ごとに分ける
- キーを使う API 呼び出し（Jev、要約・接続テスト）は Rust から出し、キーを WebView の JS に渡さない。JS はキーの保存・削除・保存済みかどうかだけを Rust に頼む
- 設定画面はキーの値を出さず「保存済み」と出し、差し替えと削除だけできる
- IndexedDB に残っている既存のキーは、キーチェーンを使う版の初回起動時にキーチェーンへ移し、IndexedDB から消す

## 前提になった実測

- 素の Tauri の窓・NSWindow の collectionBehavior 変更は全画面スペースに出ない。tauri-nspanel 2.1.0 で NSPanel にすると出る
- WKWebView ではユーザー操作なしで AudioContext が running になり、speechSynthesis も発話する
- Rust から osascript で Ghostty の一覧取得・tty 指定 focus ができる（AppleScript の `tell application "Ghostty"` の中で `tab` は tab クラスになるので区切りは `character id 9`）
- Rust 側 tauri 系 crate は npm 側 `@tauri-apps/api` 2.11 に合わせて 2.11 系に固定している

## 配布

- `bun run tauri build` の .app を `/Applications/tomarigi-desktop.app` に置いて使う
- Info.plist に `NSAppleEventsUsageDescription`（Ghostty 操作の許可ダイアログの文言）を入れる
