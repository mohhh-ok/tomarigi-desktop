- The × at the right end of the header hides the window (bring it back from the menu bar icon). Its label says "hide window", not "close", so it isn't mistaken for leaving settings or a dialog
- The header and the row under it (the tabs, or the debug log's Back row) stay at the top; only the content below them scrolls. The add-folder dialog follows the same rule: its title and × stay in view and only its content scrolls
- The debug log is a screen of its own: it replaces the tabs' content under the header (the header buttons stay), shows a "‹ Back" row in place of the tabs, and closes with Back, the debug button again, or Esc.
- Settings: ⚙ in the header opens the settings window, or brings it to the front (see "Settings window")
- Single instance (tauri-plugin-single-instance). A second launch shows the existing window and exits
- Window mode: switch between floating and standard windows, from the settings screen or the menu bar menu
  - Floating (default): a floating NSPanel (tauri-nspanel). Transparent, frameless, always on top, and shown above full-screen spaces too. It can be dragged from anywhere on its background. The window has a shadow. The app stays out of the Dock and Cmd+Tab (activation policy Accessory)
  - Standard: can be maximized or made full screen with the title bar buttons; not pinned on top. Shown in the Dock, Cmd+Tab, and with its own app menu bar (activation policy Regular). Switching back to floating restores Accessory
  - Info.plist includes `LSUIElement`, so the Dock icon doesn't flash at launch
  - In both modes, the first click on the window while another app is in front already reaches the content, so a bird or the window can be dragged without clicking once to activate it (`acceptFirstMouse` in `src-tauri/tauri.conf.json`; the user asked for it)
- The chosen mode is saved and used on the next launch. Position and size are saved separately per mode and restored on the next launch. On first launch (no saved position, or the saved position isn't on any display) the window goes to the top-right of the main display
- The menu bar menu (the taskbar menu on Windows / Linux), top to bottom: Show / Hide, Settings…, separator, Floating / Standard window (checked), separator, "Read aloud" (checked), separator, Update, Quit (issue #5; the user asked for sound toggles in the menu and chose only "Read aloud" from "Notify with sound", "Read aloud", and volume steps)
  - "Read aloud" is the same setting as the settings screen's "Read aloud" checkbox, with the same label in each language. Switching it in either place changes the other, so both always show the same value
  - It can be switched while the window is hidden
  - Where the system has no speech engine, the item is disabled, as the settings checkbox is
- The window background is translucent and blurs what's behind it with the macOS frosted-glass effect (to feel less imposing on screen). Text, birds, and bubbles stay at full strength. The opacity is fixed (`.page` in `src/perch/styles/base.css` and `.garden` in `src/perch/styles/garden.css`), apart from "Fade until hovered"
- The header's buttons look like one set (the user: 「uiしゅうせいして」, of the rough edges a UI check listed; which to fix and how is the parent session's decision, Claude's own).
  - Requirement: the header's buttons look like one set. Basic design: the mute button's icon is a single-color line icon like the debug, settings, and close buttons', not the 🔔 / 🔕 emoji, which WebKit draws in color; sound on and muted stay told apart as they are now (a bell and a crossed bell)
  - Detailed design (Claude's own decisions, by the session that implements it; may be changed): `MdNotifications` (sound on) and `MdNotificationsOff` (muted) from `react-icons/md` at 16px, the same Material set, size and color (`currentColor`) as the debug (`MdBugReport`), settings (`MdSettings`) and close (`MdClose`) buttons; its aria-label is unchanged, and the same text is its `title` (shown under the cursor) as the debug and close buttons have, so what a click does shows without new wording (after a user-reviewer's finding that the bell alone doesn't say it; the parent session's decision). The settings button gets its aria-label as its `title` too, so every header button has one (the parent session's decision)
