# Concierge

An AI looks at every session together and gives the user one piece of advice about what to do next (the user: 「全部をまとめて見て判断するようなのできないかな」「親子かんけいとかもあるから、それもふまえてユーザーにアドバイスして欲しいねん」「aiにあどばいすしてほしいねん」). Outside the Concierge tab it is shown, not read aloud (the user: 「よみあげのことはかんがえてなかった」「おれはとりあえず表示の話をしててん」); in the Concierge tab its new suggestions are read aloud in place of the per-session readout (see "Readout in the Concierge tab")

- Name: "Concierge" (ja: コンシェルジュ) in the UI and in code (the user chose it among アドバイザー / コンシェルジュ / マスター: 「こんしぇるじゅにしっようか」). Claude recommended it because the bird guides the user to the next session and takes them there on click; マスター was avoided because it reads like the watching parent session
- Example the user gave: A needs reply, then B needs reply, and the user answers B while leaving A. The advice should then go back to A (the user: 「Aを無視したままBを対応したとするやん。そうするとまたAが対応待ち、に戻って欲しいねん」). Other advice it should be able to give (Claude's proposals): a chick or linked session waiting on a reply that also holds up its watching parent; a linked session that finished but whose result never reached the parent; two sessions working on the same file or task
- Garden: the concierge bird whose speech bubble shows the advice. Clicking it jumps to the terminal pane of the session the advice is about (the user: 「そのアドバイザーをクリックすると該当のペインにとべるの」), the same jump as clicking that session's bird (a chick jumps to its parent's pane). With no target session, a click does nothing
  - The concierge bird's image is generated with an image model (the user: 「アドバイザーのとりは画像生成してね」). It must read as different from the session birds at a glance, in every icon set. Candidates are shown to the user before one is chosen
  - The user picks the look in settings between an owl and a penguin (the user, shown four candidates: 「bcをえらべるようにして」). The default is the owl (Claude's own decision; Claude recommended it). The choice is saved. The same image is used in every icon set (Claude's own decision)
  - It is placed, dragged, and counted for the window's automatic growing and shrinking like a session bird, and can be clicked and dragged at rest like one (Claude's own decision)
  - In the Garden it is shown only while an OpenAI / Anthropic key is saved or Local is set up (Claude's own decision). With no advice, it stays without a bubble. Without a provider the Garden doesn't show it, so a bird that never speaks doesn't sit among the sessions; the Concierge tab says what is needed instead (Claude's own decision)
- Concierge tab: a tab of its own, first in the tab row, that shows only the concierge bird with the current state of every session and the concierge's suggestions, so the window can sit small in a corner and show just what to do next (the user: 「コンシェルジュのみ表示するモード追加できるかな。にわのならびで、コンシェルジュ、にわ、...みたいな」, then 「コンシェルジュはやっぱりタブに追加して」). Before, it was a "Concierge only" mode inside the Garden, turned on from the right-click menu, a header button, and off with a "Show all" button, since the user first didn't want another tab (「たぶがふえるのはちょっといやなんよな」); the mode, its menu item, and both buttons are removed, as the tab row now does that (Claude's own decision)
  - The tab shows the concierge's picture (the look chosen in settings) in place of a word, with "Concierge" as its tooltip and accessible name, and in windows at most 400px and at most 300px wide the tabs are set tighter, like the header's buttons: with four words the row didn't fit the narrowest window (260px), the Japanese ones broken a character per line, nor even the default 340px in Japanese (Claude's own decision)
  - The Recent activity tab is named by a word of its own (`tabEventsLabel`, one word in every language: en Activity, es Actividad, de Aktivität, ...). The longer name (`eventFeedHeading`, en Recent activity) stays as the list's heading, which the tab view doesn't show (the tab's word stands for it). With the longer name, the tab broke onto two lines at 260px in English and in the other languages with a two-word name (es, fr, de, pt-BR, ru, it, nl, pl); a smaller font or tighter padding didn't fix the other languages, and keeping it on one line pushed the last tab out of the window (the user, choosing this among the ways Claude showed: 「dで」; told that "Recent activity" then leaves the screen and the tab reads only "Activity": 「いいよ」). Japanese keeps 最近の動き, which fits. Where the usual word was still too wide at 260px, the word means movement, like 動き: Greek Κίνηση, Filipino Galaw, Romanian Mișcare, Indonesian Gerak; Bulgarian has Дейност (Claude's own decisions). The Garden and Perch tabs' words that broke or pushed the row out at 260px are shorter too: Indonesian and Malay Perch Tenggeran, Vietnamese Garden Vườn and Perch Sào, Bulgarian Garden Двор (Claude's own decision, by the parent session: the same fault). The row is measured at 260px in every language from a build, headless
  - The tab is always shown, with or without a provider (the user: 「コンシェルジュはapikeyがなければひょうじすらされないけど、それをやめて、コンシェルジュの利用にはapikeyがひつよう、とひょうじするようにしてくれる？」「にわ、とかはつかえます、みたいなのも」). Before, it was shown only while a key was saved or Local was set up, so a user without a key never learned the concierge existed
  - Without a provider (no OpenAI / Anthropic key saved and Local not set up), the tab shows the concierge bird with its bubble saying that the concierge needs an OpenAI / Anthropic API key or Local AI, that the Garden, Perch, and Recent activity work without a key, and a button that opens the settings screen's AI section. No state lines, no suggestions, and no request is made. The window shrinks to the bird and this bubble as in the tab with a provider. Once a provider is set up, the tab turns into the usual concierge without a relaunch, and back when the last one is removed. Translated in every locale (the wording and the button are Claude's own decisions)
  - The open tab is saved and opened again after a relaunch, whichever tab it is (Claude's own decision: before, no tab was saved and the app always opened on the Garden, while the "Concierge only" mode was saved; a ?tab= in the query still chooses the tab at launch for screenshots)
  - Opening it shrinks the floating window to the concierge bird and its bubble, toward the edges it sits near (the display's thirds, as in "Layout"); a longer bubble grows it the same way. Leaving it for the Garden puts the window back to the exact frame it had just before, so every bird comes back at the same place on screen; Perch and Recent activity keep that frame as before (Claude's own decision, carried over from the mode, which the user approved with 「おk」)
  - At rest it fades like the Garden. The tab row is hidden at rest, so a label right under the handle says which tab this is, with the number of other birds and how many of them need a reply, e.g. 「コンシェルジュ · ほか 5 羽（返事待ち 2）」, on the same dark backing as the handle; the counts keep a waiting bird from going unnoticed while the bubble is quiet (carried over from the mode: the user, 「こんしぇるじゅだけひょうじもーどだということがわかるようにしてほしい視覚的な話」; the wording is Claude's own decision)
  - The standard window shows the same tab; only the floating window resizes (Claude's own decision)
  - How it is built (Claude's own decisions, carried over from the mode): the window's width follows the concierge and its bubble and is at least what the handle's row needs with the header's buttons on it, set tighter in narrow windows (at most 400px and at most 300px wide) so the row fits the narrowest window (260px); the label sits on a row of its own right under the handle and acts as a second handle. The Garden's birds stay mounted and don't measure, place again, or save while this tab is open, and the Garden is shown again only once the window is back at its frame. A right-click on the Concierge tab opens no menu: the Garden's one item, "Arrange", has nothing to arrange there, and the WebView's own menu stays off as in the Garden. The window commands keep their names from the mode (`concierge_only_fit`, `concierge_only_end`), since what they do didn't change

  - In this tab the concierge's bubble always shows the current state of every session and the concierge's suggestions, and keeps them up to date by itself (the user: 「コンシェルジュはやっぱり自動で今の状況をこうしんしてほしいなぁ。いいほうほうないかな」, then 「おk」 to Claude's proposal).       - (the user: 「uiしゅうせいして」, of the rough edges a UI check listed; which to fix and how is the parent session's decision, Claude's own) Requirement: a Japanese line in the bubble, a suggestion or a state line, doesn't break inside a phrase in WebKit (the macOS app) either, as it doesn't in Chromium (a UI check found 「いちばん長く待 / っているので」 in WebKit). Basic design: a line breaks only between phrases, in every UI language whose text has no spaces (Japanese, Chinese); the state word and a finished line's time still always show, and the 3-line cap of a state line still holds. How phrases are found is the detailed design's
        - Detailed design (may be changed; by the session that implements it, after reading the code):
          - Phrases come from BudouX (Google, Apache-2.0, npm `budoux` 0.10.3; models for Japanese, Simplified and Traditional Chinese), a small model run in the page, so both engines get the same phrases. `Intl.Segmenter` with `granularity: "word"` was tried and rejected: it gives words, not phrases, and in JavaScriptCore cut 「ビル|ド」 and 「長|く」 (「テストを更新しました。ビルドが通ったので」 → テスト|を|更新|しま|した|。|ビル|ド|が|通|っ|た|ので). BudouX gave いちばん長く|待っているので|先に|返事を and テストを|更新しました。|ビルドが|通ったので|次に|進みます
          - `src/lib/phrase-break.ts`, `phraseBreaks(text, uiLang)`: the text with U+200B (zero width space) between its phrases. The model is chosen by the text, not by the UI language, since a session's text can be Japanese under an English UI: kana in it → Japanese; Han without kana → Chinese, Traditional when the UI language is zh-TW / zh-HK / zh-MO / zh-Hant, else Simplified; anything else → the text unchanged (English, Korean, which has spaces). A space inside a phrase with a kana or kanji on either side becomes U+00A0, so 「README を」 and 「 3 回まで」 don't break at their space (a phrase's leading space still may: it is between phrases); the first shots broke 「README / を更新しました」 and 「間を空けて 3 / 回まで」. A space between English words, numbers or signs stays a space: BudouX puts a run of English and the particle after it in one phrase (「Add retry logic to the API handler and update the tests を」), and with all its spaces U+00A0 the run was one word that broke inside an English word once wider than the line. Found by splitting the phrase at its spaces, not with a lookbehind (`(?<=…)`), which WebKit before Safari 16.4 (macOS 13.3) fails to parse when the script loads. No break is put before a trailing 「…」, so a cut line's 「…」 never starts a line alone. `hasPhrases(text)` tells whether a text is one of these
          - Where it is used (concierge-status-report.tsx): a suggestion's text, a state line's text, the names, and a stale suggestion's 「now」 label. The state word is one nowrap part as before
          - CSS: `word-break: keep-all` in place of `auto-phrase`, on the parts that hold such a text only (`.concierge-status [data-phrased]`; the report sets the attribute on a name, a suggestion's text, a state line's text, or a 「now」 label with phrases, all drawn through one part, `Phrase` in `concierge-status-report.tsx`, so a text added later can't miss it; the state line's cut measures with the same `drawn`), so kanji and kana break only at the U+200B (and at spaces), with `text-wrap: pretty` kept on the whole bubble. Not on the whole bubble: in WebKit keep-all also stopped the break after a hyphen, and the first shots wrapped the English name 「tomarigi-desktop-advice- / links」 differently from before. The bubble's `overflow-wrap: anywhere` (speech-bubble.css) stays, so a phrase wider than the line (a long path) still breaks rather than overflowing. One mechanism in both engines; auto-phrase is dropped since it would only do the same in Chromium. A probe in Playwright at 100px, 12px: WebKit normal いちばん長 / く待ってい / るので先に, keep-all with U+200B いちばん長く / 待っているので / 先に返事を / お願いします。; Chromium the same with keep-all
          - The 3-line cap: `clampText` is unchanged and still cuts the raw text by graphemes (kanji and kana anywhere, a spaced word whole). StateLineText's `fits` lays out `drawn(cut, ": ")` (the 「: 」 before the text and `phraseBreaks`, the same function the line is drawn with) + 「…」, the form that is shown, so the cap is measured on the phrase-wrapped layout; the state word and time are after the text as before, so they always show
          - Cost: the models are JavaScript objects bundled into the app (ja 24 KB, zh-hans 68 KB, zh-hant 68 KB unminified); measured in a `vite build`: the JavaScript grew from 623,908 to 742,624 bytes (+119 KB; gzip 194,583 → 256,786, +62 KB), loaded from disk by the app. BudouX's `commander` and `linkedom` are for its CLI and Node DOM and are not in the bundle (neither name is in the build's JavaScript)
          - U+200B is invisible and skipped by screen readers; text copied from the bubble carries it (the bubble isn't meant to be copied from)
          - Tests: `tests/phrase-break.test.ts`, a table over `phraseBreaks` (Japanese, Simplified and Traditional Chinese, English and Korean unchanged, mixed Japanese with paths, a trailing 「…」, empty). Checked on screen with tools/concierge-tab-shot.mjs, which also writes each bubble line's text as laid out, line by line (`<NAME>-<width>-lines.txt`), so a break inside a phrase is found in the text, not only by eye
          - Requirement and basic design → where: no break inside a phrase in WebKit → U+200B + keep-all (both engines); every language without spaces (Japanese, Chinese) → model chosen by kana / Han in the text; the state word and time always show → unchanged order, the state stays a nowrap part after the cut text; the 3-line cap → `fits` measures the phrase-wrapped form; suggestions and state lines both → phraseBreaks on both in the report
