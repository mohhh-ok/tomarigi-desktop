# Download page

The GitHub Release lists about 11 files (the installers plus the updater's signatures, `latest.json`, and `.app.tar.gz`), and many people can't tell which one to take (the user: 「いまのgithubのreleaseだとどれをだうんろーどすればいいかわからないひとおおいとおもうねん。せんようぺーじあったほうがいいかな」, then 「おk」 to Claude's proposal below)

- A page of its own at `https://moh-tech.net/tomarigi/desktop/` (English at `/en/tomarigi/desktop/`), in the `moh-tech-net` repo (static files, deployed on push to main). Not a section of `/tomarigi/`, which is the Chrome extension's page and says it makes no network requests, unlike the desktop app (Claude's own decision)
- The page detects the visitor's OS and shows one main download button for it: macOS `.dmg`, Windows `-setup.exe`, Linux `.deb` / `.AppImage`. The other OSes' files and the VS Code / Cursor extension (`.vsix`) are listed below it, smaller. The updater's files (`.sig`, `latest.json`, `.app.tar.gz`) are not shown
- Every download link is GitHub's `https://github.com/mohhh-ok/tomarigi-desktop/releases/latest/download/<name>`, so a click always downloads the file directly and the page isn't edited for each release. For that, each release also carries copies under names without the version: `Tomarigi-macOS.dmg`, `Tomarigi-Windows-setup.exe`, `Tomarigi-Linux.deb`, `Tomarigi-Linux.AppImage`, `Tomarigi-VSCode.vsix`, uploaded by the release workflow (names are Claude's own decision). Before, links were built in the browser from the GitHub API, whose limit for visitors without a login is 60 requests an hour per IP; when it failed, the "Download" button opened the Releases page instead (the user: 「くりっくでちょくせつだうんろーどじゃないのはちょっとさぎやな」). A Cloudflare Worker calling the API was the other option; the copies were chosen since they need no code or token on the site (the user: 「ふぁいるめいのこぴーにしようか」)
  - The version number and file sizes shown under the button still come from the GitHub API (cached in the browser); when it fails they are just not shown
  - v0.10.0, released before this, gets the copies added by hand
- The page also carries what README's "Install" says that a first-time user needs: requirements, first launch on macOS and Windows SmartScreen, jumping to the terminal pane (permissions, kitty, VS Code extension), and updates
- README, the GitHub Release notes, and the extension's page `/tomarigi/` link to it
- The page has no link to the Chrome extension's page (the user: 「chrome拡張機能のりんくははずして。あっちはもうほとんどめんてなんすしてないしやるきもない」)
- The moh-tech.net top page (`/` and `/en/`) links Tomarigi to this page and doesn't list the Chrome extension's Tomarigi. The top page itself is specified in the moh-tech-net repo's `docs/top-page.md`
- The page shows what the app looks like: the four screenshots of README's gallery (`docs/images/gallery-1..4-*-<en|ja>.webp`, the language of the page) with their captions, so a visitor sees the app before downloading (the user: 「てかだうんろーどぺーじにすくしょいれろよ」). Where and how they are laid out is Claude's own decision
- A "Why Tomarigi?" section compares it with other tools for the same job (the user: 「できればwhy tomarigi？もほしいんだがな。他のたとえばdotsとかgrokbotとかclaude agentsとかの比較みたいなそういうかんじの」, then 「おk」 to Claude's proposal below). Claude's own decisions:
  - Compared with tools that watch or manage local agent sessions (e.g. AgentDock, Vibe Island, Claude Code's `claude agents`), and also with OpenAI's dots and xAI's Grok Bot, since many visitors know them (the user: 「Dots,grokbotは有名だからいれたいんだよなぁ」). dots and Grok Bot run their own agents in the cloud rather than watching the agent CLIs on your machine; the comparison says that plainly, as a difference in approach, so they aren't judged on points that don't apply to them (Claude's own decision)
  - Only facts checked on each tool's official page or repository go in; anything that couldn't be checked is left out, not written as "no". The table says "as of <month year>" and links each tool's source
  - claude agents: the row says, from its official page, that background sessions run under a supervisor process and keep running after the terminal is closed until they are stopped. The "who Tomarigi suits" paragraph adds, as the author's own experience and apart from the facts in the table, that background sessions that keep living on (the user: 「claude agentsはエージェントがゾンビ化するのが嫌だったんだよおれのけいけんから」) didn't suit the author; Tomarigi only reads the sessions you run in your own terminal and keeps no process alive (Claude's proposal, the user: 「おk」)
  - What the other tools do and Tomarigi doesn't (approving or replying from the overlay, usage and cost, worktrees and PRs, SSH, mobile) is stated too, and the section says who Tomarigi suits
- It is aimed at the v0.10.0 release (Claude's own decision)
