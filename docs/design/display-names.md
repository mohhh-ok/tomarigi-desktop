# Display names

- A session's display name is used everywhere it is named: the bird's name in the Garden, Perch, Recent activity, the concierge's request and advice, and the summary's lines
- When two or more sessions on screen would show the same display name (e.g. two sessions in the same project and the same agent folder), each of them is told apart, so the user can tell which is which (the user: 「なおして」, on Claude's report that two app-p sessions showed as two identical lines in the summary). How (Claude's own decision):
  - By the session's own name from the agent when it has one and it differs from the base name (e.g. Claude Code's session name such as 「tomarigi-desktop-advice-links」), since it says what the session is for
    - Only a name the user gave counts: Claude Code's `--name` / `/rename` (`nameSource: "user"` in `<config>/sessions/<pid>.json`). The name Claude Code makes up itself (`nameSource: "derived"`) is the project's name with a random suffix (「app-p-cc」「app-v-b8」, seen on the user's machine), which says nothing about the session, so those get a number (Claude's own decision)
    - Other agents' sessions get a number: Codex's thread name (`session_index.jsonl`) and OpenCode's session title are made from the first request (「未登録画面に3つの訴求を追加して」「New session - 2026-10-18T00:31:23.765Z」), sentences that don't fit in a bird's name and can't be told apart from a name the user gave. Gemini CLI, Qwen Code and Copilot weren't looked at (no sessions of theirs on the user's machine) (Claude's own decision)
  - Otherwise, or when that still leaves two the same, by a number in the order the sessions started (「app-p 2」); the first one keeps the plain name
    - The start is the process's start (Claude Code's `startedAt`); sessions without one come after those with one, then by id, so the numbers stay the same from one scan to the next. A number whose name is already on screen is skipped (「app-p 3」 when a project is named 「app-p 2」). When a session leaves, the others are numbered again among those still on screen (Claude's own decision)
  - The label of the agent folder (「app-p (claude2)」, for the same project in two folders) comes first; the session name or number tells apart what is still the same within a folder (Claude's own decision)
  - Sessions whose names don't collide keep the name they have today
  - Where a name is cut with "…" to fit (the bird's name in the Garden, Perch rows, Recent activity cards), the end that tells it apart (the folder's label, the rest of a session name that starts with the project's name, the number) stays visible: the end takes at most half the width and the start the rest, each cut with "…" (「tomarig…-advice-…」「app-s… 2」), so both the project's name and what tells it apart can be read; a short end such as a number shows whole. Cutting the start first left 「t…-a…」 in Perch at 260px, which the UI check couldn't tie to its project. Without this, 「tomarigi-desktop-advice-links」 was cut to 「tomarigi-desktop…」 in the Garden and 「app-s-long 2」 to 「app-s-lo…」 in Perch at 260px, the same as the other session (Claude's own decision, from screenshots and a UI check). A Recent activity card keeps the name its event had; the end is kept visible while that is still the session's name. The summary's lines and the concierge's advice wrap and aren't cut
  - What is set per project, not per session (the icon set's rows in Settings), is named by the project's name, without the session name, number or folder label (Claude's own decision: the row for tomarigi-desktop showed 「tomarigi-desktop-advice-links」, one session's name)
- In Perch, when a row is too narrow for the name and the state with its elapsed time on one line (the narrowest windows), the state and time go to a second line under the name, so the name gets the row's whole width. At 260px the row left the name 64–87px, and every name was cut (「app-s-lo…」, 「t… -…」) along with the state (「返…」) (Claude's own decision, after user-reviewer and the UI check flagged the 260px Perch as unreadable)
  - It is decided row by row: a row goes to two lines when its name's whole width and its state word's and elapsed time's (the working dots included) don't fit on one line next to the bird; the tool name and the request excerpt don't count, as they take only what is left. Rows that fit stay on one line, at any window width (the parent session's decision, (a) of two options: 「1 行に収まっている行を変えない」). Measured with the same-project preset: at 260px every row goes to two lines; at 300px 「tomarigi-desktop」 (149px) and 「tomarigi-desktop-advice-links」 do; at 340px only 「tomarigi-desktop-advice-links」 does; at 480px it still does (its state had been cut to 「つ…」 there). Before, it switched by the window's width (300px or less), which left the long name's state cut at 340px and 480px
  - The widths are the texts' own widths, not what the layout gave them, so a row's answer is the same on one line or two and it doesn't flip back and forth; they are measured again when the window's width or what the rows show changes, and once the fonts have loaded (Claude's own decision). Rows of peers indented under a watching parent are measured with their own, narrower width
  - A tool name that doesn't fit whole after the state and elapsed time, on the line they are on, is left out and takes no width, so on a row on one line the state stays at the row's right end like on the other rows. Hidden but still laid out, it had kept 「ついばみ中 · 9秒」 of blog next to its name at 300px while the other rows had theirs at the right end (Claude's own decision, after a UI check)
  - The second line starts under the name, not under the bird, and holds the state word, elapsed time, the working dots and the tool name, none of them cut; the request excerpt isn't shown (there was no room for it on the first line). A row on two lines is 46px tall, working rows included; a row on one line stays 24px. The tool name sits on the same baseline as the state word, at every width (it had been 4px higher, from an empty pseudo-element taken as its baseline; Claude's own decision, after a UI check)
